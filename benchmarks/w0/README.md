# W0 — воспроизводимые эталонные чертежи и измерение baseline

**Задача:** получить измеримый baseline *существующего* конвейера CadRecon перед W1/W3. Это тестовая инфраструктура, не внедрение новых OCR/CAD-функций. **Приоритет W1** — векторные PDF, **W3** — растровые источники.

## Текущее состояние W0

Генератор `generate_fixtures.py` создаёт 4 проекта с ground truth и SHA256, без внешних зависимостей, исходников клиентов, персональных данных или закрытой документации. Его результаты **синтетические**: они проверяют предсказуемые дефекты, но **не оценивают реальную производственную точность**. Файлы генерируются в `test-results/w0-goldens/`; их можно не хранить в Git.

| Fixture | Источник | Эталон | Что измеряем |
|---|---|---|---|
| `native_curves.pdf` | Векторный PDF | 2 линии, 1 PDF rect, 1 окружность из четырёх cubic Bézier, TEXT `6000` и `R20` | Фрагментация, создание параметрических окружностей/прямоугольников, сохранение текста |
| `native_ctm.pdf` | Векторный PDF | 2 линии в разных q/cm/Q координатных состояниях, текст | Ошибка концов отрезков относительно точных PT-координат, преобразование с поворотом |
| `scan_clean_300dpi.png` | 900×600 PNG | 3 линии и окружность R80 px | Ложные/найденные кандидаты (без претензии на полноценный F1) |
| `scan_degraded_300dpi.png` | PNG | Те же исходные объекты, но искусственные разрывы, фрагменты окружности и шум | Fail-safe/abstention и прирост точности на ухудшенных источниках при W3 |

**Независимое основание:** все геометрические координаты заданы в `generate_fixtures.py`, не вычислены из результата распознавания; `manifest.json` содержит SHA256 и source truth. В `native_curves` окружность именно *представлена* PDF Bezier paths, а не присутствует как специальная PDF-«окружность»: критерий W1 — корректно распознать CAD CIRCLE по допуску, не заявляя «первичный круг гарантирован».

### Команды

```bash
python3 benchmarks/w0/generate_fixtures.py --out test-results/w0-goldens
npm install
npm test
npm run build
npx playwright test e2e/w0-baseline.spec.ts
```

Playwright запускает **текущий интерфейс**: импортирует PDF/скан, сохраняет native project JSON, не изменяет вручную сущности. Диагностические результаты записывает в `test-results/w0-{vector,ctm,scan}-baseline.json` и выводит префикс `W0_DIAGNOSTIC` в Actions log. При отсутствии эталона реальных размеров не рассчитывать ошибки скана в мм; scan baseline содержит *пиксельные* показатели. Масштаб PDF PT (25.4/72 мм на листе при UserUnit=1) не равен длине в координатах модели без заданного drawingScale.

### Что эти тесты НЕ делают

- Не утверждают полноту извлечения vector paths и не доказывают precision/recall на real drawings.
- Не делают OCR на русских надписях/ЕСКД и не измеряют CER/WER.
- Не измеряют интеграцию AutoCAD/КОМПАС или DWG/CDW; независимый `ezdxf` CI уже покрывает лишь форматный smoke.
- Не проверяют векторизацию всех сканов и **не засчитывают** отсутствие кандидата как корректное восстановление.
- Не используют дорогие OCR/GPU-модели, поэтому smoke fixture можно запускать на каждом PR.

## Требования к закрытому реальному корпусу перед W1 exit gate

Подготовить минимум 10 разрешенных реальных *исходных* vector CAD PDFs + native CAD (DXF/CDW или измеренная разметка) с основными типами линий, блоками, разрезами, обычными/повернутыми размерами. Для W3 отдельно минимум 10 разрешенных сканов из независимых проектов в различных DPI/сложности. Это **минимальный пилот для обнаружения дефектов**, не статистически достаточный benchmark для 99% утверждений.

Для каждой пары документировать `case_id`, источник/владелец, разрешение, контрольные размеры в мм, DPI или Unknown, форматы/версии, `ground_truth_source`, правила adjudication инженером, раздельный train/dev/test split на уровне проекта, записи о времени обработки, точности и false-positive. Конфиденциальные файлы и лицензированные справочники — только закрытое хранилище с ревизиями/доступом, **никогда в публичный Actions artifact**.

**Acceptance W0:** reproducible synthetic fixtures+manifest, machine-readable W0 baseline, ADR-0001/2/3 согласованы, утверждены пороги/метрики, есть легальные реальные эталоны и описанные ограничения. Без реального корпуса W0 может быть **partially completed**, но «W1 готов к полноценной приёмке» заявлять нельзя.
