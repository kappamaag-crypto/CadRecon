[Инженерная сводка](docs/ENGINEERING_UPDATE_2026-11-23.md) · [мастер-промпт](MASTER_PROMPT.md).

**Архитектура утверждена 22.11.2026:** [STATIC_PAGES_ARCHITECTURE.md](docs/STATIC_PAGES_ARCHITECTURE.md). **Никакого собственного сервера, облачных OCR-очередей, платной инференс-инфраструктуры или загрузки чертежей на сервис CadRecon нет и не планируется.** Всё основное выполняется на ПК пользователя в браузере с GitHub Pages. Более сильные языковые/ML-модели загружаются пользователем по требованию. Ultra — исключительно необязательный модуль на его же компьютере.

**Решение о продукте:** 3D, STEP, генерация видов/разрезов из 3D и полноценный 3D CAD **исключены**. W4 заморожен как дополнительная ручная коррекция. Основная работа — W1/W2/W3 PDF/сканы → 2D DXF. [Актуальный scope](docs/RECOGNITION_FIRST_SCOPE_2026-11-22.md).

**Приоритет развития:** сначала максимальная практически достижимая точность **веб-версии**, затем её эргономика и производительность; дополнительный Ultra не должен быть обязательным. DXF — приоритетный открытый формат. DWG/CDW — только через совместимые лицензированные адаптеры в будущем.

## Продолжение W3/W4 — браузерная точность и безопасное CAD-редактирование

- [x] **Централизация растрового штриха:** новый модуль `src/inkCenterline.ts` уточняет Hough-LINE по медиане поперечного сечения связной чёрной краски. Без перепрыгивания белого зазора и без присвоения `verified=true`. Unit-тесты на плотные/соседние линии и пересечения.
- [x] **Безопасная очистка автоотрезков:** переработана команда удаления дублей: теперь требуются положительное геометрическое перекрытие, общее происхождение и слой, строгая проверка соосности. Даже маленький положительный промежуток не достраивается. Ручные и подтверждённые объекты не трогаются.
- [x] **Длительные пробелы чернил:** помимо доли опоры LINE на исходное изображение W3 определяет максимальный непрерывный белый участок, снижает эвристическую оценку и показывает диагностическое замечание; геометрию не удаляет. Результат входит в CSV/XLSX/ZIP.
- [x] **W4 JOIN:** после явного выбора двух открытых LINE/POLYLINE с точно совпадающими концами можно создать одну редактируемую сущность, одно Undo восстанавливает оба исходных объекта. Недопустимы пробелы, T-стыки, двойные совпадения, самопересечения и скрытая проверка геометрии.
- [x] **CI:** unit, независимый DXF, сборка, Playwright; ошибки новых browser-тестов исправляются до релизной приёмки. [Actions](https://github.com/kappamaag-crypto/CadRecon/actions).

**Честное ограничение:** на синтетике W0 с тремя прямыми и окружностью после централизованной обводки сохраняется 273 кандидата LINE в чистом и 264 в деградированном варианте. Для 2x upsample — 824. Это не доказательство высокой точности: нужен разрешённый реальный CAD/scan корпус, оценка precision/recall, независимый round-trip и проверка КМ/КМД.

## W2 — онлайн-OCR для технических чертежей (RU/EN)

- [x] **Два профиля Tesseract.js 6:** стандартный одношаговый (все фрагменты в исходном разрешении) и усиленный (повторный `PSM.SINGLE_LINE` для слабых/мелких строк, ограниченное 1.5–3× увеличение, контраст на Canvas; до 60 повторов вручную, 35 в интегрированном Browser Accurate). Только браузер пользователя, модели RU/EN загружаются в локальный кеш.
- [x] **Текст/размеры без скрытых исправлений:** совпадающие подписи перекрывающихся тайлов объединяются пространственно; конфликтующие чтения `6000`/`8000` получают диагностическое замечание, а замена допускается только при большом приросте OCR confidence и низкой исходной оценке. `verified=false` сохраняется; кириллические/латинские похожие знаки не конвертируются в исходном тексте.
- [x] **Вертикальные надписи:** opt-in `+90°/-90°` по тайлам (каждый ≤1600×1600); до 8 тайлов полностью, при большем размере — до 8 выбранных с явным предупреждением о неполном охвате и использованием OCR области. Координаты bbox переводятся назад с учётом смещения тайла. Реальные КМ/КМД ещё не аттестованы.
- [x] **OCR области:** инструмент рамки из двух углов, исходное изображение локально вырезается (до 6 Мп), проходит выбранный OCR-профиль, bbox и текст переносятся обратно в исходные координаты и доступны в «Проверке распознавания»; отмена, повторный запуск без одинаковых дублей.
- [x] **Измеримость:** `src/ocrMetrics.ts` вычисляет CER/WER, полноту и точность привязки к размеченным bbox, точную долю критических размерных надписей. Тесты пока на синтетических словах и геометрии, а не на реальных разрешённых чертежах.
- [ ] **P0 реальные КМ/КМД:** получить размеченные пользователем эталонные сканы штампов, размеров, обозначений допусков, осевых подписей, вертикальных надписей, Cyrillic/Latin; подтвердить изменение CER/WER и critical exact match сравнением стандартного/усиленного режимов и ручной проверкой. Комбинированные символы и таблицы не гарантированы.

[Инструкция OCR](docs/OCR_ENGINEERING_2026-11-22.md) · [Протокол испытаний](docs/OCR_BENCHMARK_2026-11-22.md) · [GitHub Actions](https://github.com/kappamaag-crypto/CadRecon/actions).

## Новая итерация — W1/W3/W4, интерфейс CAD

- [x] **Закрытие вкладок чертежей:** у каждого листа кнопка `×`, подтверждение, резервная копия, Undo, безопасное открытие пустого листа после закрытия последнего. Правая панель на настольном экране расширена до 352 px; мобильные размеры адаптированы.
- [x] **W3 штриховые и осевые:** отдельный браузерный пиксельный классификатор повторяющихся штрихов и «длинный–точка» (`src/linePattern.ts`) предлагает типы `DASHED`/`CENTER` для редактируемого LINE. Отсутствующие участки не считаются сплошными линиями; результаты `verified=false`. Стиль сохраняется в DXF, очищается от дубликатов только внутри одинакового типа. Есть синтетический E2E импорт PNG → Worker → JSON → DXF.
- [x] **W4 размеры:** два клика для простого размера и три клика для размещения, кандидаты «Авторазмер выбранного» / «Авторазмеры линий и окружностей» с `sourceId` и Undo. У неоткалиброванных листов число `?` вместо выдуманных мм. Диаметр окружности пока создаётся как выноска, не как ассоциативный DIMDIAMETER.
- [x] **W4 геометрические инструменты:** ограниченные `STRETCH` отдельной вершины открытой LINE/POLYLINE, зеркальная **копия** `MIRROR` по двум точкам и прямоугольный `ARRAY` до 100 элементов (до 99 новых копий), с Undo. Не выдавать за полные AutoCAD/КОМПАС реализации сложных ассоциативных операций.
- [x] **Тип линии в свойствах LINE:** вручную можно переключить `CONTINUOUS`, `DASHED`, `CENTER` и использовать инструмент «Штриховая линия». После правки признак инженерной проверки сбрасывается.
- [x] **W1 ограниченное clipping:** для подтверждённых осевых прямоугольных PDF W clipping path LINE обрезаются к видимой области; q/Q сохраняет графическое состояние. Для кривых, масок произвольной формы, прозрачности и XObjects сохраняется предупреждение; W1 не закрыт.
- [ ] **Приёмка на реальных чертежах:** КМ/КМД, собственные PDF и сканы с разрешённым использованием, независимая проверка геометрии и OCR, нативный DXF round-trip в КОМПАС/AutoCAD, F1 и мм после калибровки. Реальный DWG/CDW требует лицензированного локального SDK и не реализуется сервером Pages.

Пошагово: [инструкция пользователя](docs/CAD_WORKSPACE_2026-11-22.md). - [x] **Исправлен пропуск осевых горизонтальных/вертикальных штрихов в скане.** Детекция границ производится по всем пикселям тайла и лишь затем выбирается ограниченная выборка для Hough. На синтетике W0 покрытие трёх исходных линий в пределах 4px: **0/0/74,8% → 100/100/100%**; деградированный скан: **94,7/96,0/96,0%**. См. [отчёт W3](docs/W3_RASTER_QUALITY_2026-11-22.md). **310 фрагментов на 3 линии и окружность — проблема ложных повторов остаётся!**
- [x] Строгие W3 Playwright gates по известной геометрии: чистые линии >=97%, повреждённые >=85%, проверка окружности, не более 700 line candidates. Не переносить результаты на произвольные реальные чертежи.
- [x] Клиентский OCR на больших листах: перекрывающиеся тайлы до 1600px, координатные смещения, удаление только совпадающих OCR-полей, ограничение числа тайлов 100; отмена Web Worker и OCR. При недоступных моделях OCR браузерная геометрия остаётся доступна.
- [x] Гибридный PDF можно принудительно обработать как растр **вместе** с исходными векторами, вместо молчаливого пропуска сканированных фрагментов.
- [x] Импорт многостраничных TIFF (до 20 страниц с явным предупреждением), ограничение размера и совокупной нагрузки PDF, предупреждения о пропущенных страницах и снижении разрешения.
- [x] Все новые ручные объекты **не считаются проверенными** по умолчанию; редактирование/калибровка сбрасывают утверждение. В DXF не заявляются миллиметры без калибровки, показывается счётчик непроверенных объектов.
- [x] Проверка JSON проекта запрещает сторонние image URL, SVG подложки, опасные DXF newline, бесконечные координаты/ресурсные бомбы.

**Продолжение P0:** архитектура [GitHub Pages](docs/STATIC_PAGES_ARCHITECTURE.md); снизить **false positives 310 фрагментов**, проверить точные централи/топологию/разрывы; real CAD corpus, мобильная RAM, W1 clipping/XObjects; обеспечить достоверный отчет потерь без ложных обещаний.

## Дополнительный этап по сверке истории, мастер-плана и задач — 22.11.2026

**Сверено:** [master plan](docs/ONLINE_CAD_RECONSTRUCTION_PLAN.md), [GitHub issues #2–#9](https://github.com/kappamaag-crypto/CadRecon/issues), [политика GitHub Pages](docs/STATIC_PAGES_ARCHITECTURE.md). Очерёдность **P0: W1/W2/W3 → W4/W5 → W6 optional**; облачный W2 отменён, Ultra не обязателен.

- [x] **W1, честная геометрия PDF:** декодер теперь отличает настоящие painted paths (OPS.stroke/fill) от `endPath`, `clip` и `eoClip`. Невидимые пути не превращаются в CAD-LINE. При clipping/graphics state/Form XObject создаётся предупреждение о **неполной семантике**; реальное вычисление clipping и полная XObject-геометрия ещё **НЕ реализованы**. Добавлен реальный PDF.js 5.x E2E эталон `e2e/w1-clipping.spec.ts`.
- [x] **W2, review UI:** отдельные категории непроверенной геометрии, OCR и размеров/ЕСКД, ограниченная выдача до 60 кандидатов на страницу и переход к редактированию/удалению. Балл обозначен **эвристическим**, не вероятностью точности. Никакой автоматической `verified=true`.
- [x] **W3, безопасная дедупликация:** на распознанной окружности исключаются лишь повторные короткие круговые штрихи; для прямых сравниваются пиксели чернил между близкими Hough-гипотезами, а параллельные штрихи с белой разделительной полосой сохраняются. Исправлено неверное старое сравнение только `a.x` и `b.y`, из-за которого **разные диагональные отрезки могли исчезать**.
- [x] **W3, объяснимая оценка кандидатов:** `lineEvidence.ts` проверяет, какая доля предсказанного LINE опирается на тёмные пиксели исходника (с проверкой нормали), и **только понижает** эвристический балл неподтверждённых штрихов. Геометрию не удаляет, `verified` не меняет. Панель review сортирует сомнительные объекты первыми; прозрачное объяснение сохранено в `Entity.reason`. Не путать ink support с вероятностью правильной CAD-семантики.
- [x] **W3, качество/разрешение:** после исправления некорректного удаления диагоналей: в чистом синтетическом растре **276 LINE**, в повреждённом **264 LINE**, покрытие линий **100/100/100%** и **94,7/96,03/96,03%** @4px соответственно; при программном удвоении размера до 1800×1200 — **993 LINE**, 100/100/100% @8px. Это НЕ испытание реального 600DPI сканера и НЕ recall/F1. Контроль на сканах воспроизводим, избыток фрагментов остаётся критическим.
- [x] **W4, редактор:** реализованы `OFFSET` прямого LINE и двухточечный `BREAK` (удаление выбранного внутреннего промежутка, сохранение двух отдельных LINE). Обе команды используют явный выбор пользователя, отказывают на неоднозначных/нулевых случаях, оставляют `verified=false` и используют один Undo. Полилинии/дуги/эллипсы, ассоциативность и прочие CAD-операции ещё требуют работы.
- [x] **P0 защита проекта:** JSON-проверка отклоняет некорректное `verified`, неполные CAD-примитивы, произвольные remote images и недопустимые поля, без добавления облачной инфраструктуры.

**Дальше критично:** сократить сотни Hough-кандидатов до непрерывных редактируемых централи/полилиний **без заполнения реальных разрывов**, проверить на независимом разрешённом CAD/scan корпусе, калибровку и OCR КМ/КМД. Следующий выходной gate — error/coverage/F1 + независимый CAD round-trip, а не только прохождение unit-тестов.
