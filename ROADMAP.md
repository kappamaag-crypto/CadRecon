# ROADMAP — CadRecon (GitHub Pages, browser-first)

**Архитектура утверждена 22.11.2026:** [STATIC_PAGES_ARCHITECTURE.md](docs/STATIC_PAGES_ARCHITECTURE.md). **Никакого собственного сервера, облачных OCR-очередей, платной инференс-инфраструктуры или загрузки чертежей на сервис CadRecon нет и не планируется.** Всё основное выполняется на ПК пользователя в браузере с GitHub Pages. Более сильные языковые/ML-модели загружаются пользователем по требованию. Ultra — исключительно необязательный модуль на его же компьютере.

**Приоритет развития:** сначала максимальная практически достижимая точность **веб-версии**, затем её эргономика и производительность; дополнительный Ultra не должен быть обязательным. DXF — приоритетный открытый формат. DWG/CDW — только через совместимые лицензированные адаптеры в будущем.

## Актуальное состояние и контроль

| Wave | Статус | Что уже сделано | Что пока не подтверждено / следующий gate |
|---|---|---|---|
| W0 — измерения | частично | Синтетические эталоны PDF/сканов, измерения, ADR | Набор разрешённых реальных CAD↔PDF и сканов, инженерный sign-off — [#3](https://github.com/kappamaag-crypto/CadRecon/issues/3) |
| W1 — нативный PDF | частично | PDF.js packed paths, линии/контуры/окружности/Bezier, текст, unitless DXF, SPLINE; есть strict E2E | clipping, XObjects, полная семантика и real-world benchmark — [#4](https://github.com/kappamaag-crypto/CadRecon/issues/4) |
| **W2 — Accurate Browser** | первая версия | Объединённый pipeline **в браузере**: native PDF priority, scan trace + OCR RU/EN + размерные/ЕСКД-кандидаты, защита от повторов; загрузка языковых моделей по запросу | Реальные замеры качества, тесты на разных устройствах, модельные WebGPU packs, offline-кэш — [#5](https://github.com/kappamaag-crypto/CadRecon/issues/5) |
| W3 — сканы | частично | Детальный тайлинг/обводка, окружность на пересечении (на одном synthetic 0→1) | Связность линий, дуги/эллипсы/сплайны, OCR по разрешённым реальным чертежам, precision/recall — [#6](https://github.com/kappamaag-crypto/CadRecon/issues/6) |
| W4 — CAD инструменты | частично | POINT, прямоугольник, TRIM, EXTEND, фаска, сопряжение, Undo | OFFSET, SNAP, BREAK, JOIN, STRETCH и сложные примитивы — [#7](https://github.com/kappamaag-crypto/CadRecon/issues/7) |
| W5 — размеры/ЕСКД | частично | Номинальные цепочки, расхождения, неверифицированные кандидаты | Полный versioned ruleset и нормоконтроль по нормам — [#8](https://github.com/kappamaag-crypto/CadRecon/issues/8) |
| W6 — Ultra **на ПК пользователя** | необязательный эксперимент | Выбор папки установки Windows, Python/CPU тестовый профиль, localhost OCR API | Простая установка без Python, GPU/CPU, автономные модели, обратная совместимость — [#9](https://github.com/kappamaag-crypto/CadRecon/issues/9) |
| W7 — DWG/CDW | отложено | DXF и экспорт данных доступны | Лицензии SDK, совместимость с AutoCAD/КОМПАС-3D, независимые round-trip тесты |
| W8 — качество и релиз | в работе | CI сборка, unit и Playwright, первые synthetic accuracy gates | Независимый корпус реальных чертежей, usability/performance/security и release gates |

**Исторические документы с Online Accurate API и удалённым сервером больше не являются заданием к реализации.** Архитектуру заменила [browser-only спецификация](docs/STATIC_PAGES_ARCHITECTURE.md). Исходная расширенная инженерная программа [сохранена](docs/ONLINE_CAD_RECONSTRUCTION_PLAN.md) как источник требований геометрии/ЕСКД, а не как требование облака.

## Новые результаты браузерного P0 — 22.11.2026

- [x] **Исправлен пропуск осевых горизонтальных/вертикальных штрихов в скане.** Детекция границ производится по всем пикселям тайла и лишь затем выбирается ограниченная выборка для Hough. На синтетике W0 покрытие трёх исходных линий в пределах 4px: **0/0/74,8% → 100/100/100%**; деградированный скан: **94,7/96,0/96,0%**. См. [отчёт W3](docs/W3_RASTER_QUALITY_2026-11-22.md). **310 фрагментов на 3 линии и окружность — проблема ложных повторов остаётся!**
- [x] Строгие W3 Playwright gates по известной геометрии: чистые линии >=97%, повреждённые >=85%, проверка окружности, не более 700 line candidates. Не переносить результаты на произвольные реальные чертежи.
- [x] Клиентский OCR на больших листах: перекрывающиеся тайлы до 1600px, координатные смещения, удаление только совпадающих OCR-полей, ограничение числа тайлов 100; отмена Web Worker и OCR. При недоступных моделях OCR браузерная геометрия остаётся доступна.
- [x] Гибридный PDF можно принудительно обработать как растр **вместе** с исходными векторами, вместо молчаливого пропуска сканированных фрагментов.
- [x] Импорт многостраничных TIFF (до 20 страниц с явным предупреждением), ограничение размера и совокупной нагрузки PDF, предупреждения о пропущенных страницах и снижении разрешения.
- [x] Все новые ручные объекты **не считаются проверенными** по умолчанию; редактирование/калибровка сбрасывают утверждение. В DXF не заявляются миллиметры без калибровки, показывается счётчик непроверенных объектов.
- [x] Проверка JSON проекта запрещает сторонние image URL, SVG подложки, опасные DXF newline, бесконечные координаты/ресурсные бомбы.

**Продолжение P0:** архитектура [GitHub Pages](docs/STATIC_PAGES_ARCHITECTURE.md); снизить **false positives 310 фрагментов**, проверить точные централи/топологию/разрывы; real CAD corpus, мобильная RAM, W1 clipping/XObjects; обеспечить достоверный отчет потерь без ложных обещаний.

## Дополнительный этап по сверке истории, мастер-плана и задач — 22.11.2026

**Сверено:** [master plan](docs/ONLINE_CAD_RECONSTRUCTION_PLAN.md), [GitHub issues #2–#9](https://github.com/kappamaag-crypto/CadRecon/issues), [политика GitHub Pages](docs/STATIC_PAGES_ARCHITECTURE.md). Очерёдность **P0: W1/W2/W3 → W4/W5 → W6 optional**; облачный W2 отменён, Ultra не обязателен.

- [x] **W1, честная геометрия PDF:** декодер теперь отличает настоящие painted paths (OPS.stroke/fill) от `endPath`, `clip` и `eoClip`. Невидимые пути не превращаются в CAD-LINE. При clipping/graphics state/Form XObject создаётся предупреждение о **неполной семантике**; реальное вычисление clipping и полная XObject-геометрия ещё **НЕ реализованы**. Добавлен реальный PDF.js 5.x E2E эталон `e2e/w1-clipping.spec.ts`.
- [x] **W2, review UI:** отдельные категории непроверенной геометрии, OCR и размеров/ЕСКД, ограниченная выдача до 60 кандидатов на страницу и переход к редактированию/удалению. Балл обозначен **эвристическим**, не вероятностью точности. Никакой автоматической `verified=true`.
- [x] **W3, безопасная дедупликация:** на распознанной окружности исключаются лишь повторные короткие круговые штрихи; для прямых сравниваются пиксели чернил между близкими Hough-гипотезами, а параллельные штрихи с белой разделительной полосой сохраняются. Исправлено неверное старое сравнение только `a.x` и `b.y`, из-за которого **разные диагональные отрезки могли исчезать**.
- [x] **W3, объяснимая оценка кандидатов:** `lineEvidence.ts` проверяет, какая доля предсказанного LINE опирается на тёмные пиксели исходника (с проверкой нормали), и **только понижает** эвристический балл неподтверждённых штрихов. Геометрию не удаляет, `verified` не меняет. Панель review сортирует сомнительные объекты первыми; прозрачное объяснение сохранено в `Entity.reason`. Не путать ink support с вероятностью правильной CAD-семантики.
- [x] **W3, качество/разрешение:** после исправления некорректного удаления диагоналей: в чистом синтетическом растре **276 LINE**, в повреждённом **264 LINE**, покрытие линий **100/100/100%** и **94,7/96,03/96,03%** @4px соответственно; при программном удвоении размера до 1800×1200 — **993 LINE**, 100/100/100% @8px. Это НЕ испытание реального 600DPI сканера и НЕ recall/F1. Контроль на сканах воспроизводим, избыток фрагментов остаётся критическим.
- [x] **W4, редактор:** реализованы `OFFSET` прямого LINE и двухточечный `BREAK` (удаление выбранного внутреннего промежутка, сохранение двух отдельных LINE). Обе команды используют явный выбор пользователя, отказывают на неоднозначных/нулевых случаях, оставляют `verified=false` и используют один Undo. Полилинии/дуги/эллипсы, ассоциативность и прочие CAD-операции ещё требуют работы.
- [x] **P0 защита проекта:** JSON-проверка отклоняет некорректное `verified`, неполные CAD-примитивы, произвольные remote images и недопустимые поля, без добавления облачной инфраструктуры.

**Дальше критично:** сократить сотни Hough-кандидатов до непрерывных редактируемых централи/полилиний **без заполнения реальных разрывов**, проверить на независимом разрешённом CAD/scan корпусе, калибровку и OCR КМ/КМД. Следующий выходной gate — error/coverage/F1 + независимый CAD round-trip, а не только прохождение unit-тестов.
