# Разбор пользовательских архивов и перенос полезных идей в CadRecon

Дата статического анализа: 2026-11-22. Статус первоначального этапа: **исследование и требования**; последующая **браузерная реализация** зафиксирована в разделе 5 и в [инструкции](GALS_SEARCHTEXT_IMPLEMENTATION_2026-11-22.md). Сами бинарные файлы в GitHub не публиковать; не запускать непроверенные макросы и EXE на рабочей станции. Источники: два архива, приложенные к задаче; пересказ основан на фактически открытых файлах.

## 1. «КОМПАС ГАЛС 1-23(1).zip» — исследовано

ZIP содержит один файл «КОМПАС ГАЛС 1-23.xlsm» (около 8 МБ) с VBA-проектом, семью листами, формулами и текстовой инструкцией на листе «ИНФО». **Это подтверждает заявленное назначение функций, но не факт их работоспособности на КОМПАС-3D v25**: макросы не выполнялись. Другие листы: «ДАННЫЕ ПРОЕКТА», «ОТЧЕТ по СПЕЦИФИКАЦИИ СБЧ», «ОТЧЕТ по ОБЪЕКТАМ ЧЕРТЕЖА», «СВАРКА СТАНДАРТЫ», «Стандартные или Прочие Изделия», «Штамп Копия».

Функции, реально описанные в листе «ИНФО»:

| Номер | Обнаруженная функция | Требование к CadRecon | Приоритет |
|---|---|---|---|
| 1 | Создание структуры проекта по обозначению с выбираемыми подпапками для КОМПАС, SOLIDWORKS, STEP, архива, PDF, DXF | Шаблоны именования проекта и пакетов результатов; **в браузере — скачиваемый ZIP**, а не доступ к произвольным папкам | P2 |
| 2 | Выбор существующего каталога проекта | Импорт множественных листов/файлов с явным разрешением браузера; у локального Ultra — каталог по выбору пользователя | P2 |
| 3 | Пакетное заполнение «Обозначение», «Наименование», «Раздел спецификации» по именам и классификатору стандартных изделий | Поля метаданных, правила разбора обозначений, журнал предложенных/принятых исправлений, ручное утверждение | P2 |

| 7 | Запись позиций спецификации в сборку | Контроль совпадения позиционных обозначений на листе/в таблице; обратная синхронизация — только через отдельно согласованный КОМПАС-коннектор | P2 |
| 8 | Отчет по графическим элементам: окружности, дуги, прямоугольники, полигоны, эллипсы, обозначения позиций, выноски, текст и техтребования | **Востребованная функция:** инвентаризация CAD-объектов; обнаружение одинаковых отверстий/радиусов, пропущенных и повторяющихся позиций, неизвестных выносок | **P1** |
| 9 | Таблица сварных швов по выноскам, обозначениям, типам, числу мест на виде; список стандартов со ссылками | Связать выноску ↔ шов ↔ вид ↔ таблицу, проверка неназванных/повторённых швов и количеств, экспорт отчета, профиль стандартов | P2 |

Также наблюдались: редактируемый словарь стандартных/прочих изделий и переводов (сотни записей), классификация по ГОСТ/ОСТ/EN/ASME/DIN/ISO/SAE, лист с перечнем сварочных стандартов, поля подписантов и лист отчета по объектам с типом, параметрами, стилем, количеством и расположением. Не копировать весь чужой справочник без проверки лицензии и корректности; ввести отдельно проверяемую базу терминов с редактором.

**Ограничение применимости.** ГАЛС описывает автоматизацию *нативных* документов и 3D-связей КОМПАС. После PDF→CAD нельзя автоматически восстановить исходную параметрическую модель, сборку и связи с ведомостью: возможны только семантические кандидаты и контролируемый импорт из реального КОМПАС-проекта через SDK.

### Предлагаемый сценарий

Реконструкция → «Аудит объектов» → таблица по типам и слоям → группировка одинаковых отверстий, радиусов и сварных обозначений → связка позиции и спецификации → исправление конфликтов в CAD-редакторе → отчет ошибок/CSV/XLSX/PDF по запросу → проверенный DXF и (при наличии коннектора) CDW.

## 2. «SearchTextApp v1.5.zip» — частично исследовано

**Фактический формат вложения — RAR5**, хотя файл назван `.zip`. Внутри только `SearchTextApp v1.5.exe` (~4,1 МБ), Windows PE32+ x86-64 GUI, признаки Embarcadero/Delphi VCL. Статические строки содержат `SearchTextApp` и `Local\\SearchTextApp_KOMPAS3D_v13_SingleInstance`. **Нет исходников, руководства, формального списка функций и воспроизводимого безопасного теста интерфейса.** Бинарный EXE извлекался только для статического чтения строк; не исполнялся. Не утверждать, что программа умеет конкретные виды OCR, пакетный поиск или замены.

Возможное направление, **не подтвержденное этим архивом и требующее отдельной проверки**: модуль поиска по распознанным надписям/штампам/техтребованиям с переходом к соответствующему bbox на листе, списком совпадений, поиском по проекту и фильтрами «обозначение/материал/позиция/шов/масштаб». Эти функции полезны независимо от того, имеются ли они в исполняемом файле.

Для подтверждения возможностей потребуется запуск исключительно в изолированной Windows VM без сети, с одноразовыми тестовыми чертежами и контрольными снимками экрана/операций, **после отдельного согласования**; не внедрять чужой бинарник и не интегрировать его без проверки права использования.

## 3. Решения для постановки в backlog

- **P1 online:** отчет инвентаризации геометрических примитивов; краткий поиск по OCR с подсветкой на подложке; проверка пропущенных/повторных позиций; редактор штампа и dry-run; связывание выносок с размерами и объектами.
- **P2 online:** табличные отчеты об отверстиях/радиусах/сварных швах; классификаторы стандартных изделий; пакетная обработка метаданных и листов; история изменений.
- **P2 Ultra/КОМПАС:** двусторонняя синхронизация спецификаций и нативных данных *только при наличии подтвержденных API/лицензии*; недоступное для PDF описание 3D-сборки не выдумывать.
- **Защита от ошибки:** исходное значение, предложение и исправленное значение хранятся раздельно; операции с группами — сначала preview/dry-run, затем явно подтверждаемая транзакция/Undo.

См. [основной план](ONLINE_CAD_RECONSTRUCTION_PLAN.md), [матрицу технологий](TECHNOLOGY_EVIDENCE_2026-11-22.md), [тестовый план](VALIDATION_AND_TEST_PLAN.md).


## 4. Повторная проверка исходных архивов и новые статические доказательства (22.11.2026)

**Сравнение двоичных файлов:** повторно приложенные `SearchTextApp v1.5(1).zip` и `КОМПАС ГАЛС 1-23(2).zip` побайтово совпадают с первоначальными архивами `SearchTextApp v1.5.zip` и `КОМПАС ГАЛС 1-23(1).zip` (сверены SHA256). Оба изучены без запуска программ, макросов и EXE.

### SearchTextApp — функциональность подтверждена точными строками EXE, а не исполнением

Из единственного RAR5-файла извлечён для **статического** анализа PE64 `SearchTextApp v1.5.exe` (4 100 096 байт), SHA256 `995cf0053359a2f0579322d41eb71cf41414c40169b9867039596d166c496f22`. В UTF-16LE-строках обнаружено название интерфейса **«Поиск по чертежу КОМПАС-3D (v1.5)»** и следующие элементы управления:

- `Поиск позиций`, `Поиск размеров`, `Поиск в тех.требованиях`, `Поиск в таблицах`, `Обычный текст`, `Поиск линий-выносок`.
- `Поиск по всем файлам`, `С учетом регистра`, `Дубликаты в тех.требованиях`, ввод `Введите текст или часть значения для поиска`.
- `Найденные объекты. Выберите строку для перехода.`, `Подсветка`, `Снять подсветку`, сообщения о невозможности определить вид / получить bounding box / приблизить выбранный объект.
- Строки счётчиков по позициям, размерам, текстам, выноскам, техтребованиям, таблицам, строкам/совпадениям и ссылки на `KompasAPI7_TLB`, COM API5, `КОМПАС-3D V23`.

**Изменение к первоначальному заключению раздела 2:** исходников и руководства по-прежнему нет, работоспособность неизвестна, но реальные интерфейсные категории и диагностические сценарии **действительно присутствуют внутри EXE**. Это более сильное подтверждение проектных возможностей, чем одно название приложения. Надпись `Поиск по всем файлам` не доказывает обработку всех файлов; одновременно есть `Поиск по активному 2D-документу`. Совместимость с КОМПАС-3D v25 **не проверена**. Нельзя приписывать этому ПО OCR сканов, PDF или DWG.

**Предлагаемый W2→W5 модуль CadRecon `Поиск на чертеже` (P1, без сервера):** индекс локально распознанных PDF-text/OCR и пользовательских TEXT, размеров, позиций, выносок, таблиц, штампов и технических требований; поиск подстроки/регистра/всех листов; выдача «источник → лист/вид → bbox → тип → confidence → переход на холст → подсветка». Отдельный детектор **только буквальных дубликатов техтребований**, далее семантические похожие формулировки лишь после проверки. Никакого автоматического изменения по совпадению.

### ГАЛС — уточнение структуры `.xlsm` и практически полезных полей

ZIP содержит только `КОМПАС ГАЛС 1-23.xlsm` (7 993 885 байт); внутри есть макрос `xl/vbaProject.bin`. Макрос **не запускался**. Документальные сведения подтверждаются содержимым `ИНФО` и заголовками отчётов:

- `ОТЧЕТ по ОБЪЕКТАМ ЧЕРТЕЖА`: **расположение на чертеже, связанный объект, вид объекта, три пары параметр/значение, количество объектов, стиль линии/текста**. Заготовка листа до 12 327 строк **не означает** наличие такого числа фактически распознанных объектов.
- `ОТЧЕТ по СПЕЦИФИКАЦИИ СБЧ`: **позиция, обозначение, наименование, количество, раздел спецификации, материал, масса**, пути к связанным сборке, чертежу, спецификации. Эти связи доступны в КОМПАС-модели, но **не восстановимы автоматически из одного PDF**.
- `ИНФО`: поиск повторяющихся позиций и элементов; подсчёт однотипных отверстий/радиусов; таблица сварки с видами и числом мест, выделением выносок и предупреждением об отсутствии обозначения; пакетное заполнение штампов со свойствами подписантов.
- `Стандартные или Прочие Изделия`: **431 непустое наименование** с англо-русскими терминами из 2 962 форматированных строк. Это **редактируемый словарь**, а не подтверждённый полный нормативный классификатор и не свободно лицензированный набор для публикации.

**Предлагаемый W5-модуль `Инвентаризация и контроль` (P1):** реестр примитивов, тип/слой/источник, параметры, позиция на листе, группировка совпадающих окружностей и радиусов **в рамках калиброванного масштаба**; сравнение извлечённых позиционных обозначений со спецификацией/таблицей, пропуски/дубли/неоднозначности, локальный экспорт CSV/JSON и только проверенные версии XLSX. `Сварные швы` и `Штампы` — следующая стадия с отдельной проверкой ЕСКД, без автоматического приписывания ГОСТ.

### Приоритет внедрения по принятой архитектуре

1. **Не откладывать W3 и W1:** пока на трёх линиях/окружности остаются сотни кандидатов и не реализовано полное clipping, высокоуровневая семантика должна иметь предупреждения и не подтверждать геометрию.
2. **Ближайший независимый P1:** `Поиск на чертеже` (по уже распознанным данным и с переходом к bbox), `Аудит объектов` (инвентаризация, одинаковые отверстия/радиусы, статистика непроверенных, локальный экспорт). Эти функции дают пользу и на уже существующих цифровых PDF.
3. **После контрольных измерений:** сопоставление позиций со спецификацией, таблицы сварных швов, технические требования и штампы с preview/dry-run и журналом изменений.
4. **Только с локальным КОМПАС-адаптером:** считывание/запись нативных сборок, активных видов, спецификаций и CDW; веб-версия GitHub Pages не получает доступ к COM напрямую.

**Не переносить** чужие EXE, VBA, словари и нормы напрямую в web bundle без прав/лицензий, ревизии безопасности и проверки применимости. Все чертежи остаются на пользовательском устройстве.
