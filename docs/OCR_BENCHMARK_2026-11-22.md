# W2 OCR quality gate — сравнение с размеченными техническими чертежами

Оценщик `src/ocrMetrics.ts` работает в исходных пикселях, без миллиметров, сети или внешнего OCR-сервера. Он предназначен для **размеченных пользователем** законно используемых чертежей. Сейчас существуют unit-тесты расчёта метрик, но НЕТ проверенного реального эталонного корпуса — нельзя заявлять измеренный рост точности.

## Рекомендуемый корпус

- Не менее 20 разных разрешённых исходников КМ/КМД, PDF с изображением, TIFF и JPG; A4–A0, от 150 до 600 dpi, русский/английский.
- Разделение: размеры и допуски, обозначения отверстий/резьбы, марки стали/профилей, штампы, номера позиций, вертикальные надписи, малые шрифты, слабый контраст, перекос, пунктир рядом с текстом.
- Разметка: `id`, `text`, `x0,y0,x1,y1` в **пикселях исходной подложки**, отдельная пометка о технически критичных надписях; два независимых проверяющих для спорных надписей.
- Не помещать конфиденциальные или неразрешённые чертежи в публичный GitHub. Эталоны могут храниться локально; открытые синтетические фикстуры только в CI.

## Как пользоваться оценкой прямо в интерфейсе

1. Откройте скан, выполните OCR и зайдите в правую панель «Проверка распознавания».
2. Разверните «Измерить точность OCR по размеченному эталону JSON».
3. Подготовьте локальный файл с массивом размеченных надписей, например:

```json
[
  {"id":"stamp-name","text":"М16","x0":100,"y0":80,"x1":150,"y1":102},
  {"id":"dimension-1","text":"6000","x0":250,"y0":150,"x1":330,"y1":175}
]
```

Координаты — **пиксели исходного изображения**, а не мм и не PDF points. Их можно получить из исходного PNG/TIFF и ручной разметки.

4. Выберите JSON через поле импорта. CadRecon пересчитает bbox OCR-кандидатов из единиц листа в исходные пиксели, сопоставит их с размеченными прямоугольниками и покажет метрики. Локальный файл не отправляется в сеть.
5. Запишите результаты для быстрого и усиленного режимов на одинаковом листе и сравните. Перед повторным сравнением используйте отдельную копию проекта или очищайте результаты предыдущего OCR — сравнение всегда берёт все OCR-кандидаты текущего листа.

**Важно:** импортированный эталон не исправляет CAD-объекты; он служит только измерению качества. Если исходный скан имеет неверно заданные размеры или был преобразован при импорте, проверьте совпадение системы пиксельных координат.

## Метрики

- Пары правильной надписи и кандидата связываются по Intersection-over-Union bbox с порогом 0.45. Каждая пара используется один раз; дубли засчитываются как лишние кандидаты.
- `precision`, `recall` — обнаружение надписей по геометрии bbox; отдельно `CER` (символьные ошибки) и `WER` (ошибки по словам), включая пропущенные и лишние строки.
- `criticalExactRate` — полное точное совпадение текстов с числами или обозначениями `±`, `⌀`, `Ø`, градусами и `×`. Это не заменяет инженерную валидацию.
- Запускать для fast/enhanced/ROI и раздельно считать средние по размерам шрифта и ориентации. Публиковать обе оценки и количество пропущенных/лишних строк.
- Остановить релиз OCR-улучшений, если падает exact-match критических размерных надписей или растёт число ложных CAD-текстов сверх согласованного порога. Не оптимизировать только на одной синтетике.

Unit-тесты: `src/ocrMetrics.test.ts`, `src/ocrConsensus.test.ts`, `src/ocr.test.ts`, `src/ocrTiles.test.ts`, `src/ocrRegion.test.ts`. Скриншоты реальных чертежей с OCR-ошибками нужны для отдельной валидации.
